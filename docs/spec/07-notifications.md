# 07. 알림 정책 (MVP 확정)

## 확정 (2026-11-26)
| 항목 | 결정 |
|---|---|
| 채널 | 앱 내부 알림 + Web Push를 첫 출시에 함께 제공 (B안) |
| 승인 대기 회원 Push | 보류, 이후 개발. 첫 출시에서 가입 승인은 신청자가 앱을 다시 열어 상태 화면으로 확인. 승인 대기 화면에서는 Push 구독을 받지 않는다 |
| MVP 이벤트 | 기존 추천값에서 채널이 "없음"이 아닌 이벤트만 등록 (아래 MVP 표). 나머지는 후보 목록으로 보관 |
| 공통 규칙 | 기존 공통 정책 설계안대로 진행 (아래 공통 규칙) |

"Push + 내부"는 앱 내부 알림을 만들고 Push도 보낸다는 뜻이다.

## 공통 규칙 (확정 — 기존 설계안 채택)
- 알림 허용 요청: PWA 설치 안내 이후, 사용자가 명시적으로 허용할 때만.
- 설정: MY에서 채널별·알림 종류별로 켜고 끈다.
- OS 알림 권한을 거절해도 앱 내부 알림은 유지한다.
- 읽음: 개별 읽음, 전체 읽음, 앱 내부 미읽음 수. 앱 아이콘 배지는 OS가 지원하는 범위에서만 제공하며 동일 동작을 보장하지 않는다.
- 알림을 누르면 대상 페이지로 이동한다. 알림 링크로 원본 접근 권한을 우회할 수 없다 (서버에서 권한 재검증).
- 비활성 회원(정지·탈퇴·강퇴)에게는 Push를 보내지 않는다.
- 잠금화면에 보이는 내용의 개인정보는 최소화한다.

### 설계안에 기본값이 없어 남은 항목
설계안이 "검토"로만 적었거나 언급하지 않아 아직 정하지 않은 것. 구현 전 결정한다.
- 중복 이벤트 처리, 본인 행동 알림 제외 여부, 여러 업적 동시 달성 묶기
- 알림 보관 기간
- 권한이 사라진 대상(삭제된 기록 등)으로 이동할 때의 안내 문구

## 기술 검토
Service Worker + Push API + Notifications API, 서버측 Web Push 전송 및 구독 저장. iOS 홈 화면 웹앱의 Web Push 지원 조건/권한 요청과 Badging API, Android Chrome의 알림 기반 배지 및 제조사별 동작 차이는 실제 배포 전 최신 공식 문서와 기기에서 검증. 숫자 배지 동일 동작을 보장하지 않는다. 승인 대기 회원의 가입 승인 알림을 받으려면 제한된 화면에서 안전한 구독 흐름을 마련해야 함. Push 미설치/미허용 시 승인 상태 화면 갱신으로 확인. → 첫 출시는 승인 대기 회원 Push를 보류하고 상태 화면 갱신으로만 확인한다(확정).

## 데이터 및 처리 설계안
Notification(id, recipientId, type, targetId, payload, createdAt, readAt, dedupeKey), PushSubscription(memberId, endpoint, keys, device metadata 최소화), NotificationPreference. 이벤트 확정 후 전송, 실패 재시도/만료 구독 제거, 알림 실패로 기록 확정 롤백하지 않음. 필요 시 outbox와 배치 처리. 초기 이벤트와 수신 대상은 위 MVP 표로 확정.
