# 07. 알림 정책 (일부 확정)

## 확정 (2026-11-26)
| 항목 | 결정 |
|---|---|
| 채널 | 앱 내부 알림 + Web Push를 첫 출시에 함께 제공 (B안) |
| 승인 대기 회원 Push | 보류, 이후 개발. 첫 출시에서 가입 승인은 신청자가 앱을 다시 열어 상태 화면으로 확인. 승인 대기 화면에서는 Push 구독을 받지 않는다 |

## 이벤트별 추천값 (미확정)
아래는 가장 최근 제안 기본값이며 사용자가 아직 확정하지 않았다. Push는 앱 내부 알림도 생성하는 것을 뜻한다. 가입 승인(신청 회원) 행의 Push는 위 보류 결정에 따라 첫 출시에서 제외된다.

| 영역 | 이벤트 | 수신자 | 추천 채널 |
|---|---|---|---|
| 회원 | 신규 가입 신청 | 관리자 | Push + 내부 |

| 회원 | 가입 거절 | 신청 회원 | 없음 |
| 회원 | 기록/일정 생성 권한 부여 | 해당 회원 | 내부 |
| 기록 | 미확정 생성 | 참가자 | 내부 |
| 기록 | 미확정 수정 | 참가자 | 없음 |
| 기록 | 확정 | 참가자 | Push + 내부 |

| 일정 | 신규 일정 | 전체 | Push + 내부 |

| 업데이트 | 주요 서비스 업데이트 | 전체 | 내부 |

## 공통 정책 설계안
PWA 설치 안내 이후 사용자의 명시적 알림 허용. MY에서 알림 채널/종류별 설정. OS 권한 거절 시에도 앱 내부 알림 유지. 개별 읽음 및 전체 읽음, 앱 내부 미읽음 수, 앱 아이콘 배지(OS 지원 범위), 대상 페이지 딥링크. 알림을 통해서도 원본 접근 권한을 우회할 수 없다. 비활성 회원 Push 중단. 중복 이벤트/본인 행동 알림/여러 업적 동시 달성 묶기 정책 검토. 잠금화면 개인정보 최소화.

## 기술 검토
Service Worker + Push API + Notifications API, 서버측 Web Push 전송 및 구독 저장. iOS 홈 화면 웹앱의 Web Push 지원 조건/권한 요청과 Badging API, Android Chrome의 알림 기반 배지 및 제조사별 동작 차이는 실제 배포 전 최신 공식 문서와 기기에서 검증. 숫자 배지 동일 동작을 보장하지 않는다. 승인 대기 회원의 가입 승인 알림을 받으려면 제한된 화면에서 안전한 구독 흐름을 마련해야 함. Push 미설치/미허용 시 승인 상태 화면 갱신으로 확인. → 첫 출시는 승인 대기 회원 Push를 보류하고 상태 화면 갱신으로만 확인한다(확정).

## 데이터 및 처리 설계안
Notification(id, recipientId, type, targetId, payload, createdAt, readAt, dedupeKey), PushSubscription(memberId, endpoint, keys, device metadata 최소화), NotificationPreference. 이벤트 확정 후 전송, 실패 재시도/만료 구독 제거, 알림 실패로 기록 확정 롤백하지 않음. 필요 시 outbox와 배치 처리. 초기 이벤트/수신 대상/설정 범위 최종 선택 필요.
