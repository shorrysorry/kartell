# 05. 통계, 랭킹 및 활동 기반 업적

## 확정 방향
데이터는 플레이와 활동에 관련된 범위에서 상세히 남기되, 초기 화면에는 적은 종류의 통계/랭킹/업적만 보여준다. 업데이트로 점진 확장한다. 캐릭터/세력 및 세부 점수는 원본에 보존하고 캐릭터별 통계 화면은 제공하지 않는다. 개인 통계는 게임 단위로 제한. 모임 통계는 게임별 최고 기록 및 가장 많이 플레이한 게임 정도로 제한. 회원 종합 경쟁 랭킹이나 게임별 숙련도 업적을 초기 핵심으로 삼지 않는다.

## 통계 화면 설계안
| 항목 | 공개 범위 |
|---|---|
| 게임별 플레이 횟수, 승리 횟수/승률 | 본인 |
| 게임별 평균/최고 점수, 평균 순위 | 본인(세부 노출 최종 검토) |
| 게임별 최고 기록 보유자 및 점수 | 정상 모임원 |
| 모임 인기 게임(확정 플레이 건수) | 정상 모임원 |
| 원본 점수, 사진, 메모, 참가자 상세 | 해당 기록 권한자만 |

확정 기록만 집계 권장. 인기 게임은 참가자 수가 아니라 플레이 기록 건수로 집계. 개인 플레이는 본인이 참가한 확정 기록만 포함. 승리 정의/동점/협력 게임은 게임별 결과 규칙을 따름. 점수가 낮을수록 좋은 게임, 기본판/확장판/인원에 따른 비교 가능성은 개발자가 정한다. 공개 최고 기록에서 비참가자가 원본 상세로 이동하거나 다른 참가자의 신원을 역추적할 수 없어야 한다. 탈퇴자 최고 기록 표시/익명화 정책 미결.

## 업적 방향 (확정)
특정 게임의 세부 성적이나 숙련도보다 전체 모임 활동과 플레이 경험을 기념. 이름 옆에 달성 토큰 표시, 개인 업적 컬렉션에서 획득/미획득 및 진행도 확인. 첨부 참고 이미지의 카테고리별 다단계 메달 구조가 디자인 참고. 실제 토큰 디자인 및 등급 수/조건은 미확정.

| 후보 카테고리 | 집계 원본 | 도입 방향 |
|---|---|---|
| 전체 플레이 | 확정 참가 기록 수 | 초기 후보 |
| 전체 1위 | 경쟁 게임의 공식 1위 결과 | 초기 후보 |
| 게임 다양성 | 서로 다른 기본 게임 ID | 초기 후보 |
| 파티게임 플레이 | 게임 카테고리 + 확정 참가 기록 | 초기 또는 업데이트 |
| 전략/협력 게임 | 게임 카테고리 | 추후 후보 |
| 출석 | 실제 출석 확정 건 | 일정 기능 연계 |
| 게시글 | 유효 게시글 작성 건 | 게시판 연계 |
| 댓글 | 유효 댓글 작성 건 | 게시판 연계 |
| 게임 후기 | 유효 후기 작성 건 | 후기 기능 자체 후순위 |
| 게임 평가 | 평가한 서로 다른 게임 수 등 | 평가 기능 자체 후순위 |
| 함께 플레이한 회원 | 서로 다른 동료 참가자 | 추후 후보 |

예시 등급 1/5/10/30/50/100회, 브론즈/실버/골드 등은 프로토타입용이며 확정하지 않음. 출시 시 적은 카테고리부터 제공. 게임별 업적 카테고리는 초기 제외.

## 업적 UX 설계안
- 카테고리명, 현재 수치, 해제된 업적 수/전체 수, 획득 토큰과 회색 미획득 토큰.
- 토큰 선택 시 달성 조건, 현재 진행도, 남은 수치.
- 대표 업적 1개 설정/변경/해제(제안), 프로필 및 이름 옆 작은 토큰. 전체 컬렉션 공개 범위 미결, 기본은 본인 조회 권장.
- 표시 후보: 플레이 결과, 참가자 목록, 게시글/댓글, 최고 기록, 회원 프로필.

## 집계 및 확장 설계안
원본 활동 → 통계/업적 계산 → 파생 결과 저장 또는 조회. 업적 정의는 개발자가 코드/버전으로 추가. 신규 업적 추가 시 이전 유효 활동 소급 적용. 기록 확정, 관리자 수정/삭제, 출석 확정, 게시글/댓글 변경 시 관련 파생 데이터 재평가. 대리 생성자는 참가자일 때만 플레이 업적 반영. 중복 부여 방지, 중복 출석/도배/삭제된 콘텐츠 집계 기준 필요. 잘못된 기록으로 달성한 업적 회수 및 대표 토큰 해제 정책은 제안 단계. 획득 시각과 평가 시각을 구분할지 검토. 미구현 기능의 활동 데이터를 미리 생성하거나 불필요한 개인정보를 수집하지 않는다.
