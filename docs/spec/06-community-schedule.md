# 06. 커뮤니티 및 일정관리

## 확정 범위
초기 커뮤니티는 자유게시판 + 일정관리. 별도 후기/평점/공략 게시판, 실시간 채팅은 후순위. 기존 카카오톡 활동을 보완한다.

## 자유게시판 설계안
정상 회원 전체 조회 및 작성. 제목, 본문, 이미지 첨부, 댓글, 좋아요, 검색, 관리자 공지/상단 고정. 작성자/관리자 수정 삭제. 대댓글, 카테고리, 인기 글, 회원 태그는 후순위. 게시글/댓글/좋아요 상세 목록은 앞선 제안이며 최종 MVP 검토 필요.

### 화면
목록: 공지 우선, 최신 글, 제목/본문 미리보기, 작성자(대표 토큰), 날짜, 댓글/좋아요 수, 검색, 글쓰기.
상세: 제목/본문/이미지, 작성자, 좋아요, 댓글 입력, 권한별 수정·삭제.
작성: 제목 및 본문 필수, 첨부 선택, 입력값 검증, 이탈 시 확인.

### 데이터 및 관리
postId, authorId, title, body, photo references, createdAt, updatedAt, status, pinned/notice. commentId, postId, authorId, body, timestamps, status. 좋아요는 memberId + postId 유일성. 서버 권한/HTML 안전 처리, 이미지 접근 검증, 삭제 콘텐츠 집계 제외 방향. 도배 방지 기준 미결.

## 일정관리 확정 정책
| 항목 | 결정 |
|---|---|
| 일정 생성 | 일정 생성 권한을 부여받은 회원 및 관리자 |
| 출석 확인 | 일정 생성자 및 관리자 |
| 모집 인원 | 선택적으로 설정 |
| 참여 취소 | 모임 시작 전까지 자유롭게 |

정상 회원 일정 조회/신청 가능은 기존 설계 방향. 일정 생성 권한은 기록 생성 권한과 독립적. 참여 신청은 출석이 아니다. 실제 출석만 출석 업적에 반영하는 방향.

## 일정 기능 및 입력 설계안
제목, 시작 날짜/시각, 장소, 상세 내용, 모집 인원(선택), 생성자. 종료 시각/반복 일정 필요 여부는 미결. 인원 제한 미설정이면 무제한, 설정 시 서버에서 초과 신청 방지. 신청/취소, 참여자 목록, 실제 출석 관리, 과거 일정 조회. 일정 생성자가 자동 신청되는지, 미신청 현장 참석자 출석 처리 여부 미결.

## 일정 상태 설계안
모집 중 → 모집 마감 → 진행 중 → 종료. 취소 상태 별도 필요. 시작 시간 이후 일반 참여 취소 차단. 일정 수정/삭제는 생성자 및 관리자, 종료 후 출석 수정은 관리자만 허용하는 제안은 미확정. 일정 취소/삭제 시 출석 및 알림 영향 결정 필요. 정원에 도달했다가 취소로 자리가 생기면 재모집하는 방식 검토. 시간대 Asia/Seoul 기준으로 UI 표시, 서버 시각을 기준으로 판단.

## 데이터 설계안
Event(id, creatorId, title, startAt, place, description, capacity nullable, status, timestamps).
EventRegistration(eventId, memberId, status, joinedAt, cancelledAt).
Attendance(eventId, memberId, status, checkedBy, checkedAt). 일정·회원 조합 중복 출석 금지. 참여 신청과 출석 분리.

## 화면 및 테스트
커뮤니티 탭 내 자유게시판/일정 서브탭. 월간 캘린더/날짜 선택/일정 리스트, 상세와 신청/취소, 생성 권한자용 등록, 생성자 및 관리자용 출석 확인. 테스트: 무제한/정원 초과, 동시 신청, 시작 전/후 취소, 신청하지 않은 출석 처리 정책, 출석 중복, 권한 없는 생성/출석 요청 차단, 일정 취소 및 업적 재평가.
