# 03. 게임 데이터 및 게임별 점수 계산

## 확정 정책
- 게임 등록은 개발자 본인만 가능. 운영 관리자 및 회원은 등록/편집 불가.
- 각 게임의 점수 계산 UI와 로직은 개발자가 직접 개발하고 규칙도 직접 전달한다.
- 복잡한 계산도 별도 게임 모듈로 구현. 관리자용 범용 계산기 생성 도구 불필요.
- 확장판 선택에 따라 게임별로 다른 점수 계산 시트 제공. 검증한 조합만 지원.
- 점수 계산기가 없는 게임은 현재 기록 생성 불가. 총점 수동 입력으로 우회하지 않는다.

## 카탈로그 데이터 설계안
내부 gameId, BGG ID(선택), 한국어/원어 제목, 별칭, 출시연도, 인원 범위, 플레이 시간, 장르(파티/전략 등 복수 태그 가능), 이미지 출처 및 권리 상태, 확장판 목록, 캐릭터/세력 목록, 지원 상태. 장르 태그는 향후 활동 업적 평가에 사용한다.
지원 상태 제안: DEVELOPING / SUPPORTED / UNSUPPORTED / DISABLED. 조회 가능 여부와 신규 기록 가능 여부는 분리. 지원 중단 후에도 과거 기록은 조회 가능해야 한다.

## 모듈 구조 설계안
```text
features/scoring/
  types.ts
  registry.ts
  calculators/<game>/
    config.ts
    types.ts
    ScoreSheet.tsx
    calculate.ts
    calculate.test.ts
```
공통 기록 흐름과 저장 형태를 재사용하되 게임별 입력 UI와 계산 로직은 독립적. registry에서 gameId + 확장판 조합 + 판본/규칙 버전으로 모듈을 선택한다.
입력: 참가자, 게임 구성, 게임별 원본 입력값(라운드별/공용 보드 상태 포함 가능), 캐릭터/세력, 동점 판정 정보.
출력: 참가자별 세부 점수, 총점, 순위, 승패/결과, 적용 규칙 버전. 낮은 점수가 유리한 게임, 공동 순위, 팀전/협력 게임 등은 개별 규칙에 따르며 지원 전 별도 검토.
프론트 즉시 계산과 서버 검증은 동일한 순수 계산 함수 사용 권장. 과거 확정 결과를 새 버전으로 임의 재계산하지 않는다.

## 게임 추가 절차
1. 개발자가 기본 정보, 지원 인원 및 확장판/캐릭터 목록 제공.
2. 개발자가 실제 점수 계산 방법, 입력값 범위, 배수, 감점, 승리 및 동점 조건 제공.
3. 전용 모바일 시트 및 순수 계산 함수 구현.
4. 실제 점수표 기반 정상/경계/동점/확장판 조합 테스트.
5. 라이선스 확인 및 카탈로그 등록, 지원 활성화 후 배포.

## 초기 후보 (미확정)
아르낙, 윙스팬은 이전 프로토타입에서 예시로 사용. 니폰, 테라포밍 마스, 스플렌더, 스카우트 등도 언급됨. 실제 출시 지원 게임 목록과 공식 계산식은 아직 확정되지 않았다. 프로토타입 숫자/동점 로직을 제품 규칙으로 복사하지 말 것.

## BGG 및 이미지
실제 게임 정보와 표지 사용 희망. BGG API 연동은 후보이며 승인/등록, 비상업적 이용 조건, 캐싱/출처 표시, 이미지 재사용 권리 등은 실제 개발 전 최신 공식 약관 확인 필요. API 승인과 이미지 저작권 허락은 별개. 공식 룰북은 링크 중심, 점수 규칙은 개발자 설명을 토대로 독립 구현. 권리 확인되지 않은 표지/사진은 배포하지 않고 임시 이미지 사용.
